仓库采用 monorepo 结构：`backend/` 是 Python 工程根（包含 `surge` 命名空间包），`frontend/` 是静态站点产物，根目录仅保留跨子项目的部署与入口配置。
- `pyproject.toml` 将包名定义为 `surge`，并通过 `[tool.vercel] entrypoint = "backend.surge.worker_service:app"` 显式指向 Vercel 的 FastAPI 应用；要求 Python ≥3.13，运行时依赖为空（实际由 requirements.txt 提供）。
- `requirements.txt` 使用 `-r backend/requirements.txt` 转发，避免后端依赖与前端清单两份漂移。
- `docker-compose.yml` 仅启动一个 PostgreSQL 16 (`cp-pg`) 服务，暴露 5432 端口并带 `pg_isready` 健康检查，供本地开发连接 `SURGE_DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:5432/surge`。
- `vercel.json` 把 `backend/surge/worker_service.py` 标记为函数（maxDuration 300s），定义 `/health/deep` 定时任务及静态资源缓存与安全响应头，且 `public: false`。
- `render.yaml` 定义 Render Web Service：`rootDir=backend`，构建命令仅 `pip install -r requirements.txt`（不执行 npm），运行命令为 `uvicorn surge.worker_service:app --workers 1`，并通过环境变量注入 Supabase 存储、数据库 URL、`SURGE_FORCE_SYNC_TASKS=false`、`SURGE_AUTO_MIGRATE=false` 等生产参数。
- `.gitignore` 排除 `.env*`、`data/`、`uploads/`、`.venv/`、`node_modules/` 等敏感与构建产物，但显式例外 `!frontend/dist/**`，因为 Render 不构建前端，dist 必须入库才能被后端 StaticFiles 服务。
