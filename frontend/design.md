# 激浪（Cross-border AI Workspace）设计规范

> 版本：**3.0** · 体系：**shadcn/ui 语义层 + LinkFox Agent 布局语言 + Lucide + Motion**
> 适用：React + TypeScript 前端（Vite 构建）。样式分两层：
> **手写语义层**（`css/*.css`，7 个）+ **Tailwind 工具类层**（`css/tailwind.css`，构建生成）
> 变更：v2 → v3 **配色不动**（品牌蓝 `#1B6EF3` 保持），只借 LinkFox 的**形态与布局**：
> 大圆角、允许胶囊、68px 图标栏、内容居中单列、常驻输入框。
> 对标 <https://os.linkfox.com/>，但不采用它的紫色配色。

| 领域 | 参照 | 本项目落地方式 |
|---|---|---|

| 布局分栏 | react-resizable-panels | `src/lib/panels.ts` 的 `split()` |
| 拖拽 | dnd-kit | `src/lib/panels.ts` 的 `sortable()` |
| 状态管理 | Zustand | `zustand`（`src/stores/`） |

**现状（2026-10-30 起）**：前端已是 React + Vite，所以 shadcn/ui 与 Tailwind 已经**真正接入**
（`components.json`、`src/components/ui/`、`src/styles/tailwind.css`），见第 16 节。
Motion / 分栏 / 拖拽 / 状态仍用仓库自己的等价实现，没有换成 npm 包 —— 它们依赖的旧页面
还在陆续迁移，一次性替换的回归面太大。

> **关键发现（2026-10-22 实测）**：LinkFox Agent 的 CSS 变量与 shadcn 完全同构
> （`--color-background` / `--color-card` / `--color-border` / `--radius-lg: .5rem`）。
> 也就是说 v2 选的体系方向是对的，v3 只是把**取值和布局模型**对齐它，不需要换体系。

## 2. 设计目标与原则

激浪是跨境电商 AI 运营工作台。视觉表达**智能、行动、增长**，参照 LinkFox 的轻盈感，
不做泛化的"未来科技后台"。

核心原则：

- **品牌蓝是唯一强调色**。只出现在主操作、链接、焦点环、选中态、AI 结果标记。
  一屏蓝色面积不超过 8%。**不引入第二套强调色**（LinkFox 的紫色不采用）。
- **留白优先于边框**。内容居中单列（最大 760px），两侧留白；卡片用极浅边框，
  不再靠密集分割线撑结构。
- **大圆角 + 允许胶囊**。输入框、面板用 12–16px；模式切换、筛选项、状态标签用胶囊。
  v2 的「禁用胶囊」规则**作废**。
- **图标栏代替宽侧栏**。导航默认 68px（图标上、文字下），可展开成 208px 文字侧栏。
- **卡片零阴影**，Hover 只加深边框与底色，不抬升。
- **演示数据必须诚实标注**，不把模拟结果呈现成真实店铺数据。
- **真实交互优先**，动效不得盖过功能，且必须尊重 `prefers-reduced-motion`。

命名沿用 shadcn 语义层，页面只用语义名，不写死色值。

| Token | 值 | 用途 |
|---|---|---|
| `--background` | `#FAFAFA` | 页面底 |
| `--card` | `#FFFFFF` | 卡片、表格、输入框 |
| `--foreground` | `#111114` | 主文字 |
| `--muted-surface` | `#F8F8F8` | 表头、骨架、禁用底 |
| `--muted-foreground` | `#73737B` | 辅助文字 |
| `--border` | `#E5E7EB` | 唯一分隔线颜色 |
| `--primary` | `#1B6EF3` | 主操作、链接、焦点环、选中态 |
| `--primary-hover` | `#1560DC` | 主操作 Hover |
| `--primary-soft` | `#EFF6FF` | 图标容器底、选中底、浅色标记 |
| `--primary-line` | `#BFDBFE` | 浅色标记的描边 |
| `--ring` | `#1B6EF3` | 焦点环 |

语义色独立于主色，禁止用蓝色替代成功/警告/错误：

| Token | 值 | 用途 |
|---|---|---|
| `--success` | `#15803D` | 已完成、已连接 |
| `--warning` | `#B45309` | 等待审批、示例数据、降级 |
| `--destructive` | `#DC2626` | 失败、删除 |
| `--info` | `#2563EB` | 演示提示条、中性信息 |

**强调色配额**：一屏内品牌蓝面积不超过 8%。默认按钮白底描边，只有页面的"唯一主操作"
用 `.btn-primary`。导航选中态用**浅蓝底 + 蓝图标**，不用纯色填充。

旧变量名（`--bg` / `--surface` / `--ink` / `--brand` / `--line` …）保留为兼容别名。

## 4. 字体与字号

- 字体栈：`Noto Sans SC` → `Inter` → 系统字体（PingFang SC / Microsoft YaHei）。
  **不加载外部 Web Font**（Google Fonts 在境内不可用），本机装了即生效。
- 正文 14px / 行高 1.5；辅助 13px；元信息 12px；卡片标题 14px/500；页面标题 20px/600。
- **大标题用 600–700**（LinkFox 首页主标题字重明显更重，这是"有力"的来源）。
- 数字统一 `font-variant-numeric: tabular-nums`。
- 标题字距 `-.02em`，正文不加字距。

## 5. 形状、间距、高度

- 圆角：控件与徽章 `6px`、卡片 `12px`（`--radius-lg`）、面板与浮层 `16px`、
  胶囊 `999px`（`--radius-pill`）。**胶囊可用于模式切换 / 筛选 / 状态标签**。
- 间距只用四档主值：`4 / 8 / 12 / 16`，结构间距可用 `20 / 28`。
- 控件高度：`28 / 32 / 36 / 40 / 44`（`--h-*`），默认 32；输入区与主按钮 36–40。
- 阴影只用于浮层：卡片无阴影，Hover 不加阴影；弹层用 `--shadow-lg`。
- 侧栏 68px（收起 56px 纯图标），顶栏 48px，内容边距 20px，
  **内容最大宽度 760px 居中**。

## 6. 组件与交互模型

| 组件 | 规则 |
|---|---|
| Button | 默认白底描边；`primary` 品牌蓝底白字；`secondary` 中性填充 + 描边；`quiet` 无边框；`danger` 红描边 |
| Badge | 22px 高、6px 圆角、11px 字。语义色用浅底 + 同色描边 + 深字；示例数据必须虚线边框 |
| Card | 白底 + 1px 极浅边框 + 12px 圆角，**无阴影**；Hover 边框转 `--border-strong` |
| **技能卡片** | 左侧 32px 浅蓝圆角图标块（蓝字），右侧标题 + 分类 + 两行描述 + 标签 chips |
| Table | 无斑马纹、表头无底色，靠行分隔线；行高 44px；数字右对齐 |
| Tabs | 页面级用下划线式；控件级用 `segmented`（静默底 + 白滑块） |
| **Chip** | 28px 高，**胶囊形**；未选：浅灰底无边框；选中：品牌蓝描边 + 蓝字 + 白底 |
| **模式切换** | 胶囊组，选中项白底 + 边框 + 轻微 `--shadow-xs`，未选透明 |
| Input / Select | 32px 高、6px 圆角、`--input` 描边；聚焦品牌蓝描边 + 3px 淡蓝光圈 |
| **对话输入区** | 大圆角 16px 容器、白底、聚焦时边框转品牌蓝；底部一行工具（`+` / 技能 / 提示词库 / 发送） |
| Empty | 40px 中性图标容器 + 标题 + 说明 + 最多两个操作 |
| Skeleton | 中性底 + 透明度脉冲，不用流光扫过 |
| Toast | 浅色卡片 + 语义色图标，不用整块深色 |
| Modal / Drawer | 遮罩 `rgba(17,17,20,.5)`，浮层白底 + 1px 边框 + 大阴影 |

**布局模型（对标 LinkFox）**：

```
┌────┬──────────────────────────────────────┐
│    │                  通知 · 状态 · 账号  │  ← 顶栏（无底色，右侧浮起）
│图标│                                      │
│栏  │        ┌──────────────────┐          │
│68px│        │   页面标题（居中） │          │  ← 首屏：标题 + 模式切换
│    │        └──────────────────┘          │
│    │        [ 模式胶囊组 ]                │
│    │        [ 分类筛选 chips ]            │
│    │        ┌─────┐ ┌─────┐ ┌─────┐      │  ← 技能卡片 3 列
│    │        └─────┘ └─────┘ └─────┘      │
│    │        ┌───────────────┐            │
│    │        │  常驻输入区    │            │  ← 底部固定，主入口
│    │        └───────────────┘            │
└────┴──────────────────────────────────────┘
```

**禁止**：`backdrop-filter` 玻璃、渐变背景、彩色发光、卡片 Hover 浮起。

## 7. 动效（Motion）

统一曲线与时长，写在 Token 里，CSS 与 JS 共用：

| Token | 值 | 用途 |
|---|---|---|
| `--ease-out` | `cubic-bezier(.16,1,.3,1)` | 出现、位移（默认） |
| `--ease-in-out` | `cubic-bezier(.4,0,.2,1)` | 循环动画 |
| `--ease-spring` | `cubic-bezier(.34,1.36,.64,1)` | 选中态回弹（胶囊切换） |
| `--dur-1` | 120ms | 颜色、边框、Hover |
| `--dur-2` | 180ms | 进场、Toast、Modal |
| `--dur-3` | 280ms | 抽屉、分栏 |

`js/motion.js` 提供 `animate / fadeIn / fadeOut / stagger / inView / tap`，基于 Web
Animations API。新增动效优先用 `CPMotion`，不要在业务代码里写死 `transition` 时长。

**硬约束**：`prefers-reduced-motion: reduce` 下所有时长归零并与 CSS 同步。

## 8. 布局与交互原语

- **分栏**：`CPPanels.split(el, { storageKey, defaultSize, min, max })`。
  支持方向键 ±2%（Shift ±8%）、Home/End 到边界、双击复位；
  `role="separator"` + `aria-valuenow` 可访问。
- **拖拽重排**：`CPPanels.sortable(list, { item, onEnd })`，原生 `draggable`。
- **状态**：`CPStore.create(initializer)`，API 与 Zustand 一致。
- **响应式**：≤960px 分栏退化为上下堆叠；≤980px 图标栏只留图标；
  ≤720px 表格转卡片、技能卡片改单列、页面头改纵向。

## 9. 数据资产页面规则

- 页面标题：数据资产。说明文案以用户任务为中心，避免 "Mock / Seed / Connector" 等工程术语。
- 顶部全局提示用"演示环境"表达数据来源，不解释内部模拟实现。
- 隐藏普通用户不需要的数据源内部 ID；诊断场景按需提供。
- 字段映射下拉优先显示中文业务名称，底层 key 不变。
- 演示数据用统一"示例数据"标记，导入数据显示"已导入"。
- 不得把模拟数据标记成已连接店铺数据。
- 导入、校验、提交、错误 CSV 导出等现有接口行为必须保留。

## 10. 交互与可访问性

- 所有按钮保留 hover / active / disabled / focus-visible 状态。
- 不用颜色作为唯一状态提示；状态同时提供文字。
- 焦点环统一 `outline: 2px solid var(--ring)` + 2px offset。
- 保持键盘导航；分栏拖拽条可用方向键操作。
- 尊重 `prefers-reduced-motion`。
- 错误提示说明用户可以采取的下一步，内部堆栈留在日志。
- 移动端避免侧栏、表格和卡片产生横向溢出。

## 11. 用户可见文案

界面上只出现**用户要做的判断**和**用户能采取的动作**，不出现实现细节。

**禁止出现在 UI 里的词**：HttpOnly / Cookie / 会话凭据 / 日志 / 模型上下文 / 接口 /
端点 / endpoint / payload / schema / 注册表 / skill_key / is_mock / seed / Mock / BYOK /
哈希 / 序列化 / 事务。

**写法对照**：

| 不要写 | 改成 |
|---|---|
| 会话凭据由 HttpOnly Cookie 承载 | （直接删掉，不解释怎么实现） |
| 密码经加盐哈希后保存在数据库 | （删掉） |
| 密钥不会写入日志，也不会进入模型上下文 | 密码与密钥只用于你的账号，不会出现在任何执行结果里 |
| 数据导入：预览 → 字段映射 → 提交 → 错误 CSV | 数据导入：先预览、再校对字段，有问题可下载清单逐条改 |
| Mock 连接 / Mock 徽章 | 演示连接 / 示例 |
| 平台发布接口尚未接入 | 目前只能记录审批结论，还不会真的发布到平台 |

**原则**：

1. 说结果和边界，不说机制。诚实说明"还没接"是必须的，但不能用工程词汇表达。
2. 面向用户用业务名词（商品标题、五点描述、价格），不用字段名和内部 key。
3. 示例数据统一用「示例」标识，不用「Mock」「演示数据」混着叫。

## 13. 店铺经营助手（`/stores` 四子页）

2026-10-23 实测 `os.linkfox.com/store-assistant` 后落地。**本节覆盖 §12 中与之冲突的条目。**

### 13.1 信息架构

一页四子页，子导航在**页面内顶部**，不占用左侧 68px 图标栏：

| 子页 | 路由 | 内容 |
|---|---|---|
| 经营看板 | `/stores` | 待处理事项 → 5 段切换（概览 / 订单 / 广告 / 库存 / 售后） |
| 单品分析 | `/stores/product` | ASIN 检索 → 商品摘要 → 指标 + 走势 + 该品广告 |
| 经营明细 | `/stores/ledger?kind=` | 4 类长表（商品 / 订单 / 售后 / 库存） |
| 店铺授权 | `/stores/authorize` | 已绑店铺、各数据域来源、添加表单 |

筛选态（`range` / `seg` / `kind` / `asin`）同步进 URL，用 `history.replaceState`，刷新可复原。
**新增子页必须同时**：注册路由、加进 `TABS`、加进后端 `SPA_ROUTES`
（少一处，用户刷新就直接看到 404 的裸 JSON）。

### 13.2 实测取值（照抄 LinkFox，不再自创）

| 项 | 取值 | 用途 |
|---|---|---|
| 卡片圆角 | `8px` | `.st-card` |
| 卡片边框 | `1px solid #E7E7EA` | 边框优先，**零阴影** |
| 指标格最小高 | `82px` | `.st-metric` |
| 指标值 | `20px` + `tabular-nums` | 数字必须等宽 |
| 表头高 / 底色 | `35px` / `#FAFAFA` | `.st-table th` |
| 表格行高 | `44px` | `.st-table td` |
| 内容区 | `max-width: 1320px`、`gap: 14px` | `.page--store` |
| 状态徽标 | `22px` 高、全圆角 | `.st-pill` |
| 子导航项 | `13px` / `36px` 高 | `.st-tab` |

指标网格列数：核心 6 列、订单/库存 5 列、广告 9 列（`.st-metrics--ads`）。

### 13.3 数据纪律（这一页最容易出问题）

- **前端不造任何业绩数字**。所有数值来自 `/api/marketplace/*`；后端没给的维度就不出卡片，不摆空壳。
- **口径必须自洽**：广告销售额由近 30 天真实订单销售额反推（`ad_share = 32%~58%`），
  否则会出现「广告销售额 > 全店销售额」这种一眼假的数。
- **环比不编 0%**：上一窗口为 0 时返回 `null`，前端显示「无对比」；`|Δ| < 0.05` 显示「持平」。
  成本类指标（花费 / ACOS）用 `inverse`，涨了是坏事，颜色要反过来。
- **确定性种子**：日级 `random.Random(seed(store_key, day))`。同一天刷新数字不变，
  窗口滑动只增删一天，不会出现整条曲线跳变。
- **未绑定店铺不出空图表**，改出三步引导（选店铺 → 确认站点 → 开始同步）。

### 13.4 组件约定

- 命名空间 `.st-`，全部写在 `css/store.css`，不往 `components.css` 里塞页面级样式。
- 图标尺寸要显式给：`.icon` 基础样式**无宽高**，页面里用到的地方都得补，
  否则 SVG 撑满父容器。
- 图表统一走 `window.CPChart`（`js/charts.js`，手写内联 SVG）。
  **不准引 Recharts**——图表是手写内联 SVG（`src/lib/charts.ts`），只有折线与柱状两种，引一个图表库
  并改掉 Render 单服务托管形态。

### 14.3 表单由接口生成，不手写


表单来自 `inputs.model_json_schema()`，由 `window.CPSchemaForm` 渲染：

- 字段的 `title` **就是用户看到的中文标签**。改文案改后端模型的 `title`，不要在前端写第二份。
  嵌套对象（如 `OwnProduct`）的字段同理——模型上漏一个 `title`，界面上就会冒出 `Brand` 这种英文名。
- `x-ui` 决定控件：`hidden` / `file` / `lines` / `kv-lines` / `keyword-lines` /
  `competitor-lines` / `report-picker` / `listing-picker`。
- **枚举一律用 `Literal` 而不是 `str`**：`str` 会渲染成文本框，把 `manual`、`en-US`
  这种内部码直接印在输入框里。
- 枚举值走 `L.value()` 翻中文（`zh-CN` → 「中文」、`manual` → 「手动填写」），不直接印原值。
- 字段声明的 `default` 会作为初值铺进表单（站点 `US`、币种 `USD`、篇幅「中」），
  不让人对着空白猜默认值；空数组 / 空对象不铺。
- 空值一律不提交，让后端按「缺什么」报错，前端不替它猜默认值。

### 14.4 运行与错误

- 判定顺序固定：登录 → 角色 → 技能存在 → 参数校验 → 缺 Key → 限流 → 执行。
  **参数错误必须先于缺 Key 暴露**，否则用户填错了却被告知去配 Key。
- `428`（缺 Key）：结果区出 `.callout-warn` +「去配置 API Key」，按钮指向 `/settings`，
  不弹 toast 就完事。
- `422` 且带 `detail.errors`：按中文标签匹配到对应字段，标红 + 顶部汇总一句
  「提交的内容有几处需要修正」。**不回显英文字段名**。
- 慢技能（`competitor_analysis` / `listing_generation`）走 `async_run=true` +
  `AR.poller` 轮询，结果区先出步骤条再出内容；不要用假进度条凑时间。
- 结果里的 `is_demo` 一律翻译成「示例数据 / 这份结果基于示例数据，不能用于真实经营决策」，
  色调用 `callout-warn`，不用红色错误态。

### 14.5 组件约定

- 命名空间 `.sk-`，写在 `css/skills.css`，不往 `components.css` 塞页面级样式。
- 渲染分派留在 `js/pages/skills.js` 的 `outputHtml()`：报告走 `CPRender.renderReport`，
  Listing 走 `CPRender.renderListing`，其余按 key 出结构化区块。
- 图表（`profit_calc`）必须**等 DOM 插入后**再调 `CPChart.bars`，
  它在 `clientWidth` 为 0 时不画。
- 页面内异步渲染自带渲染序号守卫（`renderSeq`），切走时旧响应丢弃，不依赖路由层取消。

## 16. Tailwind 与 shadcn/ui 落地约定

这一节是**硬约束**，都是踩过的坑，改之前先读。

### 16.1 不用 `important`

官方为「与已有高优先级样式共存」推荐的 `@import "tailwindcss" important;` 会带来一个
不可接受的副作用：工具类的 `!important` **会压掉行内 style**。

实例：工作台曾写 `className="dash-grid mt-4" style={{ marginTop: 'var(--sp-5)' }}`，
行内的 20px 被 `mt-4` 的 16px 顶掉，整页少了 8px 高度。

因此当前策略是：

- 既有 7 个 CSS **保持无层、一行不动**；
- 新代码（`components/ui/*`、已迁移页面）**只吃 Tailwind**，不与旧类名混写同一属性；
- 个别位置确实要压过旧类时，用**单点** `!` 前缀（如 `!p-0`）——显式、局部、可搜索。

### 16.2 `tailwind.css` 是构建产物，固定文件名

后端只挂 `/css` `/js` `/media`，且靠 `?v=0` 占位符注入构建戳做缓存失效。
所以 Tailwind 不用 Vite 打包（那会变成 `css/index-<hash>.css` 绕开这套机制），
而是 `npm run build:css` 生成到固定路径 `css/tailwind.css`，作为**第 8 个样式**加载。

改样式后必须重新 `npm run build`（会先跑 build:css），否则 dist 里是旧样式。

### 16.3 `@theme inline` 不是可选项

`--background` / `--card` 等在 `:root` 定义、在 `.dark` 覆写。非 inline 的 `@theme`
会在 `:root` 处提前替换 `var()`，深色主题直接失效。`inline` 让工具类输出
`var(--background)`，按元素重新解析。

### 16.4 命名陷阱：`muted`

本项目的 `--muted` 是**文字色**（v1 兼容别名），shadcn 的 `muted` 是**面**色。
`--color-muted` 必须映射到 `--muted-surface`，映射错了 `bg-muted` 会把文字色当底色。

### 16.5 断点用原值

`src/styles/tailwind.css` 里定义了三个断点，取值与手写 CSS 完全一致：

| 名字 | 值 | 用途 |
|---|---|---|
| `shell` | 981px | 小于它侧栏退回图标栏、显示抽屉入口 |
| `wide` | 1180px | 小于它页面与顶栏收内边距 |
| `narrow` | 720px | 小于它隐藏面包屑、压缩状态标识 |

不要换成 Tailwind 默认的 768/1024/1280 —— 那会让响应式行为与改造前不一致。

### 16.6 组件分层

- `src/components/ui/`：**只放 shadcn 基元**，不放业务逻辑，不 import 业务模块。
- `src/features/*`、`src/pages/*`：业务组件写在该 feature/page 目录里。
- 需要覆盖基元样式用 `className` + `cn()`，不要改基元本身去适配某个页面。

### 16.7 外壳已迁 Tailwind，探针钩子保留

`app` 网格 / `sidebar` / `topbar` 的样式已在 Tailwind 里，`layout.css` 的对应规则
已删除。`.app` `.sidebar` `.topbar` `.nav-item` 这些类名**只作探针钩子**，不承载样式，
别照着它们写新样式。

窄屏退回图标栏由 `src/hooks/useMediaQuery.ts` 的 `useShellNarrow()` 决定
（`expanded = stored && !narrow`），不再用 `display: none !important` 硬压。

### 16.8 页面改版时，把探针从样式类名换成语义钩子

探针原来断言 `.card-grid-3 .card` / `.t-section` 这类类名，样式一改就红。
已迁移的页面改用 `data-*` 语义钩子（如 `[data-agent-card]`、`[data-agent-name]`），
断言的含义不变，但不再耦合样式实现。后续页面改版照此办理。

### 16.9 改完必须跑的三件事

```bash
npm run build   # 含 build:css，产物契约校验
npm run smoke   # 页面冒烟（含外壳与各页断言）
```

`npm run ab:tailwind` 是**接入期的一次性守卫**：它比对「带/不带 tailwind.css」
的渲染是否逐像素一致，用来证明引入 Tailwind 没有改动既有页面。外壳与已迁移页面
现在**依赖** Tailwind，摘掉它必然有差异，因此这个脚本不再作为常规检查，
只在新接入某个样式层时临时用。
